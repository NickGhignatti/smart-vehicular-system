## Goal

Build a small sensor-fusion project that tracks the lead vehicle smoothly in stop-and-go traffic and triggers a stable warning or a gentle slow-down action.

### Tools
- CARLA front RGB camera, radar and ego-vehicle speed.
- A simple constant-velocity Kalman filter to fuse distance, relative speed and object persistence over time
- A warning widget or a basic longitudinal controller

### Implementation
Implemented and tested offline; validation and tuning in CARLA pending (see [docs/PLAN.md](docs/PLAN.md)).

- [x] Detect the lead vehicle in the camera image and extract radar range/range-rate for the same target.
- [x] Associate the two measurements and fuse them with a Kalman filter to obtain a smoother estimate of gap and closing speed.
- [x] Compute a simple time-to-collision indicator and use it to warn the driver or reduce speed.
- [x] Compare camera-only, radar-only, and fused behavior in stop-and-go traffic and mild occlusion (tools ready; needs CARLA recordings).

## Validation and Deliverables
- Show that the fused estimate is less noisy and produce fewer false warnings than the single-sensor baseline.
- Deliverables:
    - [x] CARLA code
    - [x] Kalman-fusion module
    - [ ] Report with distance/TTC plots (figures generated by `evaluate`; outline in [docs/REPORT_OUTLINE.md](docs/REPORT_OUTLINE.md))
    - [ ] Demo video (`run --video`)

## Setup

The CARLA Python client must match the server version exactly. The repo pins **0.9.16** (Python 3.10–3.12); for a 0.9.15 server (lab PCs) pin `carla==0.9.15` (Python 3.7–3.10).
With [uv](https://docs.astral.sh/uv/):

```bash
uv venv --python 3.10 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt   # Linux/macOS: .venv/bin/python
cp .env.example .env    # then set CARLA_HOST / CARLA_PORT of the remote simulator
```

For notebooks, register the venv as a Jupyter kernel and select it in VS Code:

```bash
.venv/Scripts/python.exe -m ipykernel install --user --name svs-carla --display-name "Python 3.10 (SVS CARLA)"
```

## Usage

Activate the venv (`.venv\Scripts\activate` on Windows, `source .venv/bin/activate` elsewhere), then
`python -m svs <command>` (`python -m svs <command> --help` for options).

| Command | Simulator? | What it does |
|---|---|---|
| `check` | yes | read-only: versions, latency, server settings, maps |
| `sensors` | yes | ego + parked lead; camera and radar vs ground truth (radar sign check) |
| `camera` | yes | camera lead detection + gap vs ground truth, CSV in `outputs/logs/` |
| `run` | yes | a scenario with the whole pipeline live (HUD warning widget, optional ACC); saves a recording |
| `synth` | no | synthetic recordings for development / dry runs (not results) |
| `evaluate` | no | replays recordings in every mode: metrics table + report figures in `outputs/report/` |
| `calibrate` | no | sensor bias / noise from recordings -> `calibration.json` |
| `tune` | no | grid search of filter / warning parameters -> `best.json` |

Examples:

```bash
python -m svs run --scenario stop_and_go --seed 1                  # scripted driver, fused warning on the HUD
python -m svs run --scenario occlusion --seed 11 --mode camera --video
python -m svs run --scenario stop_and_go --seed 2 --control acc    # gentle slow-down controller drives
python -m svs evaluate outputs/recordings/carla                    # all recordings in a folder
python -m svs --set fusion.sigma_accel_mps2=2.5 evaluate "outputs/recordings/carla/stop_and_go_*.npz"
python -m svs --config-file config/calibration.json --config-file config/best.json evaluate ...
```

Global options (before the command): `--host`, `--port`, `--town` override `.env`;
`--set section.field=value` (repeatable) and `--config-file file.json` (repeatable) override any
config value without editing code. Scenarios: `approach` (calibration), `stop_and_go`,
`occlusion`, `cut_in`. Weather: `--weather HardRainNoon` (any `carla.WeatherParameters` preset).

Every simulator run uses synchronous mode (`FIXED_DELTA_SECONDS`, default 0.05 s), reads sensor
data matched to the simulation frame, and on exit destroys its actors and restores the server
settings, so a crashed run does not leave a shared simulator frozen.

## Workflow

1. **Simulator session** ([docs/SIMULATOR_SESSION.md](docs/SIMULATOR_SESSION.md)): checks,
   calibration runs, dataset recordings (tuning seeds 1-3, test seeds 11-13), controller, videos.
2. **Offline**: `calibrate` -> `tune` (tuning set) -> `evaluate` (test set) with the resulting
   `config/*.json`. Plan, gates and tuning knobs: [docs/PLAN.md](docs/PLAN.md).

How it works per frame (`svs/pipeline.py`, identical live and in replay):

```
clean camera boxes --noise/misses--> lead selection --> monocular gap + sigma ---+
                                                                                 +--> Kalman filter (camera | radar | fused)
radar points --degradation--> corridor + nearest cluster --> range, range-rate --+         |
                                                                                    TTC -> stable warning (HUD)
                                                                                    gap -> ACC gentle slow-down
```

## Tests

Everything except the real simulator is tested offline: perception math on synthetic scenes,
the Kalman filter (accuracy and statistical consistency), tracker life cycle, warning logic,
controller in closed loop, metrics, and every simulator app against a small fake CARLA
(`tests/fake_carla.py`).

```bash
python -m pytest            # all tests (~35 s)
python -m pyflakes svs tests
```

## Camera pipeline

`svs/perception/`, one step per module, called once per frame by `FrontCameraTracker.update()`
(the camera counterpart of Lab5's `FrontRadarTracker`):

1. **Detection** (`detector.py`): boxes around every vehicle.
   - `instance` (default): CARLA's instance-segmentation camera, aligned pixel-for-pixel with the
     RGB camera. It handles occlusion exactly; pixel noise and random misses are added so it behaves
     like a real detector.
   - `yolo` (optional): pretrained YOLOv8n on the RGB image.
2. **Lead selection** (`lead_selector.py`): nearest box inside our lane, the Lab4/Lab5 "front
   corridor" applied to boxes, with a little hysteresis so the lead does not flicker.
3. **Distance** (`camera_tracker.py` + `camera_geometry.py`), two monocular estimates fused by
   inverse-variance weighting:
   - ground plane: `d = h / tan(angle below horizon of the box bottom)`;
   - known width: `d = f * 1.85 m / box width`.
   Each comes with a 1-sigma uncertainty (it grows with d^2), which becomes the Kalman measurement
   noise. No smoothing happens here; that is the Kalman filter's job.

### Camera field of view

A narrower FOV sees *farther*; a wider one sees *wider and closer*. With 640x360 and the Lab4 mount
(1.4 m high, pitch -6 deg):

| FOV | max range (car >= 20 px) | gap error per pixel at 20 m | closest gap with wheels in view |
|---|---|---|---|
| **60 deg** (used) | ~51 m | 0.52 m | 1.7 m |
| 90 deg | ~30 m | 0.90 m | 0.5 m |

Below 1.7 m the width method still works, and the radar is very precise at short range,
so one 60 deg camera covers the whole stop-and-go range.

## Layout

```
svs/
  __main__.py          CLI entrypoint (python -m svs ...)
  config.py            .env values (machine) + parameters (code); tunables marked TUNE:
  pipeline.py          per-frame chain shared by live runs and replays
  scenarios.py         stop-and-go profile, IDM driver with distractions, events
  synth.py             synthetic CARLA-like recordings (development only)
  evaluation.py        metrics: accuracy, noise, false / missed warnings, latency
  calibration.py       robust statistics for sensor calibration
  plots.py, hud.py     report figures, live warning widget
  sim/                 CARLA plumbing: session, spawning, sensors, traffic, ground truth
  perception/          camera (geometry, detector, lead selection, tracker), radar (+ noise model), occlusion
  fusion/              measurements (common frame), Kalman filter, lead tracker (3 modes + raw baselines)
  decision/            TTC, headway, forward-collision warning
  control/             ACC gap controller, speed controller for scripted vehicles
  data/                recording format (.npz)
  apps/                one module per CLI command
config/                tuned JSON overrides (calibration.json, best.json)
docs/                  PLAN.md, SIMULATOR_SESSION.md, REPORT_OUTLINE.md
tests/                 offline tests (pytest), fake CARLA
outputs/               recordings, logs, report, videos (git-ignored)
```
